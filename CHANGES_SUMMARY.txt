# ============================================================================
# 1. NORMAL 상태에서 REPORT 생성 제외
# ============================================================================

변경전: 모든 상태(Normal, Grey, Warning, Danger)에서 report 생성
변경후: Grey, Warning, Danger 상태만 report 생성

구현 위치: agents/report_agent.py - _run() 메서드
코드:
    if predicted_class == 0:  # Normal
        return {
            'should_report': False,
            'reason': 'Normal 상태에서는 report 생성 안함'
        }

# ============================================================================
# 2. 이전 결과와 다를 때만 REPORT 생성
# ============================================================================

변경전: 매번 report 생성
변경후: 같은 상태가 반복되면 report 생성 안함

구현:
- self.last_inference_result: 이전 inference 결과 저장
- 현재 결과와 비교해서 다를 때만 report 생성

예시:
    Last:    Warning (2)
    Current: Warning (2)
    → Report 생성 안함
    
    Last:    Warning (2)
    Current: Danger (3)
    → Report 생성

# ============================================================================
# 3. RAG (VectorDB) 기반 과거 보고서 참고
# ============================================================================

추가된 기능:
1. VectorDB 초기화 (_initialize)
   - Chroma VectorDB 사용
   - OllamaEmbeddings로 embedding
   - report_db/ 디렉토리에 저장

2. 유사 보고서 검색 (_run)
   - 현재 상태 + 주요 특성 기반 쿼리 생성
   - similarity_search_with_score(k=3)로 상위 3개 검색
   - LLM 프롬프트에 포함

3. 최종 보고서 VectorDB 저장 (finalize_report)
   - 사용자 조치 + 최종 분석을 메타데이터와 함께 저장
   - 향후 유사 상황에서 참고 가능

# ============================================================================
# 4. 2단계 보고서 생성 프로세스
# ============================================================================

[1차 보고서 - 초안 (LLM 생성)]
    ↓
입력: predicted_class, top_features, similar_reports
출력: interpretation_text, recommendations
저장: report_history/draft/{report_id}.json
상태: 'draft'

[사용자 조치 입력]
    ↓
Streamlit UI의 "📄 보고서 관리" 탭
사용자가 실제 수행한 조치 입력

[최종 보고서 (LLM 생성)]
    ↓
입력: 1차 분석 + 사용자 조치
출력: final_interpretation
저장: 
  1. report_history/final/{report_id}_final.json
  2. VectorDB (Chroma)
상태: 'final'

# ============================================================================
# 5. 불필요한 정보 제거
# ============================================================================

제거된 필드:
- confidence (신뢰도) → 이제 표시 안함
- probabilities (클래스 확률 분포) → 불필요
- predicted_class (number) → level로 충분

보존된 필드:
✓ timestamp - 발생 시간
✓ level - 0~3 (숫자)
✓ level_name - 'Normal', 'Grey Zone', 'Warning', 'Danger'
✓ top_features - XAI 상위 특성 (기여도만)
✓ interpretation_text - LLM 해석
✓ recommendations - 권장사항
✓ status - 'draft' 또는 'final'
✓ user_action - 사용자가 입력한 조치 (final만)
✓ final_interpretation - LLM이 생성한 최종 분석 (final만)

# ============================================================================
# 8. Streamlit UI 변경사항
# ============================================================================

추가된 탭: "📄 보고서 관리"

기능:
1. 대기 중인 보고서 목록 표시
2. 1차 분석 내용 표시
3. 영향 특성 및 권장사항 표시
4. 사용자 조치 입력 텍스트 에어리어
5. "✅ 최종 보고서 생성" 및 "❌ 취소" 버튼

흐름:
1. Inference → Warning/Danger 상태
2. Report Agent → 1차 보고서 생성 (should_report: True)
3. Streamlit UI → "📄 보고서 관리" 탭에 표시
4. 사용자 → 조치 입력 후 "최종 보고서 생성" 클릭
5. Report Agent → finalize_report() 호출
6. LLM → 최종 보고서 생성
7. 저장 → report_history/final/ + VectorDB
8. UI → 리스트에서 제거

# ============================================================================
# 9. 주요 메서드 및 반환값
# ============================================================================

메서드: report_agent.execute(input_data)

입력:
{
    'predicted_class': int,       # 0: Normal, 1: Grey, 2: Warning, 3: Danger
    'top_features': [             # XAI 상위 특성
        {'name': 'PM10', 'contribution': 0.35},
        {'name': 'NTC', 'contribution': 0.25},
        ...
    ],
    'timestamp': str,
    'feature_names': list
}

출력:
{
    'should_report': bool,        # Report 생성 여부
    'reason': str,                # 미생성 이유 (should_report=False일 때)
    'report_id': str,             # Report ID (should_report=True일 때)
    'markdown': str,              # 마크다운 형식 보고서
    'html': str,                  # HTML 형식 보고서
    'summary': str,               # 한 줄 요약
    'json': dict                  # Report JSON 객체
}

메서드: report_agent.finalize_report(report_id, user_action)

입력:
- report_id: str                 # Draft report의 ID
- user_action: str               # 사용자가 수행한 조치

출력:
{
    'success': bool,
    'report_id': str,
    'final_report': dict,         # 최종 보고서 JSON
    'file_path': str              # 저장된 파일 경로
}
